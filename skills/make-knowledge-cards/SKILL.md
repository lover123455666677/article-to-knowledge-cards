# Make Knowledge Cards

把一篇文章转换成一组可快速复习、可自测的知识卡片。默认输出 5~8 张；卡片数量服从内容，不服从数字。

## 输出格式

输出一个 Markdown 文档：顶部一个总标题，其后每张卡片严格包含四个部分，卡片之间用 `---` 分隔：

```markdown
# 知识卡片：<文章标题>

## 卡片 1：<知识点标题>
- **核心知识**：<一句话结论，读者只看这句也能抓住要点>
- **简明解释**：<2~4 句，说清是什么、为什么或怎么做，通常不超过 120 字>
- **例子/自测**：<原文中的例子；原文没有例子时，给一个答案能在本卡片中找到的自测问题>

---
```

标题使用具体的名词短语或结论（如“缓存失效的三种策略”），不要用“知识点一”这类空标题。原文没有标题时，根据内容自拟简短标题；标题可以概括，但卡片正文不得借标题之名加入新事实。语言与原文一致。

## 工作流程

### 1. 获取并通读输入

- 一次只处理一篇文章。
- 用户直接粘贴文本：直接使用。
- 用户给出本地文件：仅接受 `.md` 和 `.txt`，用 Read 工具读取；若出现乱码，用 Python 按 UTF-8、GB18030 顺序尝试解码。
- 通读全文后再动笔，不要边读边写卡片。

### 2. 筛选知识点

候选知识点包括：定义与概念、原理与机制、方法与步骤、规则与条件、关键结论、易混淆概念的区分。

按以下标准取舍：

- 只保留读者需要记住、能用于理解或解题的内容；背景铺垫、过渡句、情绪表达、纯叙事不做成卡片。
- 例子、数据、故事本身不是知识点，它们服务于某个知识点，应并入该卡片的“例子/自测”。
- 一张卡片只讲一个知识点；一句话里出现两个并列要点，就拆成两张。
- 同一知识点在文中反复出现时合并为一张，采用最清晰的一处表述，禁止重复卡片。

### 3. 确定卡片数量

- 合格的独立知识点达到 5 个及以上：输出 5~8 张，按重要性排序，优先保留全文主干。
- 知识点超过 8 个：只选最重要的 8 张，并在末尾用一句话说明有取舍。
- 知识点不足 5 个：按实际数量输出，并在末尾一句话说明原文信息量不足，不拆分、不注水凑数。
- 全文没有可提取的知识点（如纯抒情、纯通知）：明确告知用户，不产出卡片。

### 4. 撰写卡片

- 核心知识写成一句确定的结论，不写“本文介绍了……”这类元描述。
- 简明解释只复述原文已有的因果、机制或步骤；术语、数字、人名、时间必须与原文一致。
- 例子/自测二选一即可，原文两者都支持时可都写：
  - 例子必须来自原文或由原文事实直接改写，不得虚构场景、数据和出处。
  - 自测问题用开放式提问（如“为什么 X 会导致 Y？”），其答案必须能在本卡片中找到，不出超出卡片内容的偏题。
- 谨慎对待逻辑推论：即使某个结论能从原文必然推出，只要原文没有明确写出，就不写入卡片；解释只做改写和重组，不做增补。
- 不使用原文之外的任何外部知识，不补充原文未给出的评价、延伸和常识。

### 5. 交付前自检

逐张核对，全部满足才能交付：

1. 四张卡片要素齐全，且每张只讲一个知识点。
2. 每张卡片的每个事实都能在原文中找到对应，无新增信息。
3. 卡片之间无重复、无包含关系；若一张是另一张的总论或细分，合并后重写。
4. 数量为 5~8；不足 5 张时已说明原因。
5. 例子源自原文；没有例子的卡片使用了自测问题。

默认直接在对话中输出 Markdown；用户要求保存文件时，将结果写入 `.md` 文件（本地文件输入可使用 `<原文件名>.cards.md`）。

## 边界：不支持的场景

- **网页/URL**：不抓取网页。请用户把网页正文粘贴为文本，或保存为 `.md`/`.txt`。
- **PDF、Word、图片、音视频**：不解析。请用户先转成 Markdown 或纯文本。
- **Anki（.apkg 等）**：不导出 Anki 牌组，只产出 Markdown 文本。
- **图形界面、可视化卡片图片**：不生成 GUI 程序或卡片图片。

收到不支持的输入时，说明限制并给出上述替代方式，不要尝试绕过。
